# GRS 通用审核系统

面向 QQ / Koishi 机器人的多通道 AI 内容审核系统，覆盖文本与图片。

## 版本

**v2.2.0** · 2026-09-15

## 更新信息

### v2.2.0 — 2026-09-15

- **可视化审核流程编排**：新增「审核流程」画布，把三通道审核从写死的分支改为可拖拽的 DAG（串行 / 并行 / 汇聚），文本与图像各存一套拓扑；支持保存前校验、试运行逐节点 trace
- **三层执行结构**：下限层 `floors`（敏感词预检、内容安全，只升不降）→ 主管线 DAG → 终裁层 `finalizers`。原先通过 `image.linkage` 隐式生效的 WD1.4 终裁钩子已**显式化**，可在画布上看见、禁用、追踪
- **并行合并语义**：取最严重 / 取最轻 / 以指定分支为准三种策略。**任一分支失败即整段 fail-closed**（不参与风险比较）；全部分支跳过则输出「未执行」，绝不降级为放行
- **风险序统一**：新增 `src/flow/risk.js` 作为唯一风险等级序定义源，收敛原先散落的重复定义，消除「取最严重」在不同代码路径下比较结果漂移
- **插件化扩展**：新增 nsfwjs 本地审图、关键词检测审图（对文件名 / EXIF / 标签做词库判定）、阿里云内容安全（从核心剥离为插件）三个插件；SDK 走**可选依赖**，未安装则插件自动禁用并给出安装命令，核心与其它插件不受影响
- **可用性驱动禁用态**：未就绪的服务（依赖缺失、密钥未配）在画布上置灰并显示原因与修复指引，无法被拖入流程图，杜绝「能选中但点了没效果」
- **图校验**：环、孤立节点、输出断开、模态不匹配连线等给出具体错误码与位置，非法图**零写入**配置
- **旧配置自动迁移**：双检配置与旧通道开关自动迁移为等价拓扑，升级后原有配置继续生效；保留旧引擎逃生开关一个版本（已标记 deprecated）
- **失败注入加固**：修复一处分支失败被下游节点掩盖导致的 fail-open；`status !== ok` 时判定结果强制置空，任何只读判定的消费方都无法绕过

### v2.1.0 — 2026-09-14

- **提示词注入防御**：待审内容与系统指令强隔离（随机定界 + 逃逸中和），模型输出经白名单 / 枚举 / 取值域强校验，全部失败路径 fail-closed，默认拦截而非放行
- **可选能力治理**：本地 Ollama、云端大模型、内容安全均为可选，未配置即静默跳过；修复配置缺失导致崩溃、占位符密钥被误判为已配置等问题
- **启动健壮性**：修复 Windows 批处理中文编码引发的命令解析错位；无 Node 环境时自动下载便携版（含架构探测与可执行自检）
- **插件系统解耦**：引入 host-api 契约层与 capability-broker，核心与插件双向不可见，禁用插件后核心仍可运行
- **配置冲突检测**：16 条声明式冲突规则，启动时给出规则 ID、实际生效值与消除方法
- **前端视觉重构**：暖石墨底 + 钴蓝 / 黄铜，四级景深毛玻璃，浅色 / 深色双主题
- **仓库清理**：移除调试记录、AI 会话产物与本机路径，重建干净提交历史

### v2.0.0 — 初始版本

- 三通道审核：本地 Ollama + 云端大模型 + 阿里云内容安全
- 敏感词预检兜底，critical 级词条单独命中即拦截
- 图片审核、模型对比、审核记录与统计面板
- 基于 cordis 的插件系统

## 运行

```bash
npm install && npm start
```

启动后访问 <http://localhost:11451>。零配置也可启动，此时仅执行敏感词预检；
启用更多通道请复制 `config/default.example.json` 为 `config/default.json` 并填写。
